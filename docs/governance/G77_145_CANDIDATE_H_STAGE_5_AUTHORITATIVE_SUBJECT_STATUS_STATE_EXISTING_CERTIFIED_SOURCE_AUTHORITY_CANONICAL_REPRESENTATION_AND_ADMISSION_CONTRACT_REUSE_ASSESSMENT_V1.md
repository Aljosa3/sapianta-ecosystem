## Semantic Reductions

### Candidate classification rationale

`EXACT_REUSE` fails because no existing State class has all of:

```text
owner = exact G77-131 external status-domain owner
subject = one of exact Universe/Source/Instrument pairs
domain = exact G77-131 status contract
semantics = subject status + epoch + generation + predecessor/event binding
pointer relation = exact external status State coordinate
currentness relation = subordinate to complete status vector
```

`REUSE_WITH_BINDING_CLOSURE` alone is insufficient. The closest semantic
source—G77-44's external subject-status State role—does not yet have an exact
canonical object to bind. A binding contract over an opaque pair would repeat
G77-144 B01.

`EXISTING_STATE_FAMILY_CANONICAL_SUCCESSOR_REQUIRED` is selected because:

- the external status owner, atomic effect, pointer role, State pair role,
  subject universe/order, epoch/generation/status facts, and vector-currentness
  relationship already exist constitutionally;
- the missing work is exact representation and admission, not a new status
  operation or authority capability;
- all implemented alternative State classes have different semantic owners;
  and
- one canonical successor can complete the existing generic semantic family
  without creating three role-specific or parallel State systems.

`NEW_STATE_CAPABILITY_REQUIRED` is rejected. The external owner already must
produce and atomically bind subject State/current-pointer changes under
G77-44/G77-131. Requiring a new authority, mutation API, transaction manager,
or currentness source would duplicate an existing capability.

### Subject-role family decision

```text
SUBJECT_ROLES = [UNIVERSE, SOURCE, INSTRUMENT]
REQUIRED_SEMANTIC_STATE_FAMILY_COUNT = 1
ROLE_SPECIFIC_STATE_FAMILY_COUNT = 0
```

All three G77-44 rows use the same 13-field row schema and the same
`authoritative_status_state_identity/digest` role. Role, subject artifact
type/version, subject pair, generation, epoch, and status are row/State data.
Nothing in committed evidence assigns different State authority, lifecycle,
prefix, or validator semantics by role. Three families would create avoidable
representation and validator entropy.

The successor must permit one State pair to appear for only the exact subject
it binds. Reusing the same pair across two roles is admissible only if its
canonical content itself binds both roles/subjects—which the selected generic
single-subject semantics must prohibit. Therefore normal cross-role pair reuse
fails closed.

### Pointer binding

G77-44's status row contains:

```text
authoritative_status_state_identity
authoritative_status_state_digest
authoritative_status_current_pointer_identity
status_generation
status_epoch
current_status
```

It intentionally contains no pointer digest. The pointer identity is a stable
coordinate; its authenticated value/history supplies a State pair, generation,
epoch/status context, and slot digest operationally. Adding a pointer digest
field to the status row would be an unselected duplicate representation.

The missing binding is an admission equality, not a new artifact:

```text
State.subject pair/role/domain/owner/generation/epoch/status
== StatusCurrentVersion row facts

and

external pointer read-back selected State pair/generation
== the State pair/generation admitted into that event row
```

This equality must be frozen in the same canonical successor assessment as
the State family. A separately persisted binding artifact, pointer mirror, or
secondary index is unnecessary and would create another authority/currentness
pressure point.
