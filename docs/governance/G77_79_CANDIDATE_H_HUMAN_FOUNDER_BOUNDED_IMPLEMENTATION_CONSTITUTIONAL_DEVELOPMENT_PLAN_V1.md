## Rollback and Fail-Closed Rules

- Before persisted fixture evidence, code rollback follows the separately
  authorized CDP/repository process; no constitutional state exists.
- Fixture stores are isolated and explicitly non-authoritative. They may be
  discarded only within the test authorization; production-like evidence is
  never overwritten or silently deleted.
- Every constitutional record is immutable. Recovery reads or appends the
  exact authorized successor; it never rewrites a predecessor.
- A failed CAS returns conflict/read-back. It does not retry with changed
  bytes, key, disposition, owner, time, version, or operation.
- A crash after signer acceptance remains the same logical continuation. A
  terminal outcome is read, never recomputed.
- FINAL, successful effect, activation, exhaustion, Receipt, and Dormancy do
  not roll back to OPEN/AVAILABLE or restore Founder authority.
- No genuine Human act occurs until implementation, tests, independent
  assessment, external evidence validation, and a separate activation
  authorization are complete.
- A runtime implementation report cannot self-certify activation. Production
  cutover/deployment remains a separate governed boundary.
