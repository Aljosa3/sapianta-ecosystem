## Dormancy/Termination Model

The selected policy is `DORMANT_UNLESS_CAP_UNREACHABLE`, not one-time forever
termination. Permanent termination would reproduce the same unrecoverable
liveness class after any future defect in the sole CAP entry. A reusable but
ineligible safety valve is the smaller long-term risk, provided every use
requires a fresh proof over the then-current baseline.

The proposed lifecycle is:

~~~text
DORMANT
  -> ELIGIBLE       only exact fresh proof + exact scope + confirmed assessment
ELIGIBLE
  -> AUTHORIZED     only exact Human constituent decision
AUTHORIZED
  -> CERTIFIED      only exact constituent Certification
CERTIFIED
  -> ACTIVATED_REPAIR_AND_DORMANT
                    only atomic baseline repair + read-back

any stage
  -> DORMANT_STALE  if baseline changes or ordinary CAP becomes reachable
~~~

`DORMANT` means the contract definition remains present but no repair work is
admissible. The exact eligibility predicate is:

~~~text
active ordinary CAP entry reachable
OR a complete ordinary CAP chain exists for the exact target
OR no fresh valid ConstitutionalEvolutionLivenessFailureProof exists
-> meta-repair constitutionally inadmissible

active ordinary CAP entry provably unreachable
AND exact fresh proof exists
AND zero ordinary CAP repair chain exists
AND exact minimal scope is independently confirmed
-> meta-repair may become ELIGIBLE for that repair identity only
~~~

No choice between healthy CAP and meta-repair exists. A different baseline,
target, or failure requires a fresh proof, manifest, assessment, Human
decision, Certification, and commit.
